## Domain Research

- GitHub Copilot docs, "Best practices for using GitHub Copilot to work on tasks": Copilot agent tasks work better when issues are clear, well scoped, and include acceptance criteria; GitHub also recommends research, planning, iteration, and PR review before merging agent work. Source: https://docs.github.com/en/copilot/tutorials/cloud-agent/get-the-best-results
- GitHub Blog, "Survey: The AI wave continues to grow on software development teams": GitHub surveyed 2,000 enterprise software-team respondents across the U.S., Brazil, India, and Germany; more than 97% reported using AI coding tools at work at some point, while organizational support varied by region. Source: https://github.blog/news-insights/research/survey-ai-wave-grows/
- DORA 2024, "Accelerate State of DevOps Report 2024": DORA reports AI adoption improves individual productivity, flow, and job satisfaction, but also identifies negative impacts on software delivery stability and throughput, reinforcing the need for fundamentals like small batches and robust testing. Source: https://dora.dev/research/2024/dora-report/

## LinkedIn Draft

Coding agents are making software teams faster in some places.

But they are also exposing a very old problem: weak fundamentals.

Over the last few weeks, I have seen developers use agents and still struggle to finish work quickly with quality. The issue is usually not the model.

It is the engineering around the model:

- unclear decomposition
- weak architecture/design thinking
- poor acceptance criteria
- limited test discipline
- shallow code review
- incomplete deployment understanding

An agent can generate code. It cannot fully replace the judgment needed to decide what should be built, where it belongs, how it should fail, how it should be reviewed, and whether it is ready to ship.

This matches what the better public guidance is already saying. GitHub's Copilot agent docs emphasize clear, well-scoped tasks and acceptance criteria. DORA's 2024 report also shows the tension clearly: AI can improve individual productivity and flow, but software delivery stability and throughput still depend on the basics.

My view: coding agents reward strong engineers more than they rescue weak process.

The practical skillset is still software engineering fundamentals, architecture and design, building blocks, testing, review, and deployment.

The agent is leverage. The engineering discipline is still the control system.
